## Notes

- Iteration 1 (2026-10-21): All items passed except "No [NEEDS CLARIFICATION] markers remain"; two
  deliberate markers were raised with the user (health-state scope, routing-policy interaction).
- Iteration 2 (2026-10-21): Both resolved by user decision — instance-local health behind a
  replaceable boundary (FR-020/020a/020b), and failover layered with routing policies.
- Iteration 3 (2026-10-22, `/speckit-clarify`): Four further clarifications recorded. All 16 items
  still pass.
  - Failover ships as its **own policy**, not as parameters on the routing policies.
  - Routing policies publish an **ordered preference list**; the routing algorithm is consulted once
    per request, never re-run per attempt (FR-021 through FR-024).
  - Launch adoption is `model-round-robin` + `model-weighted-round-robin` only; header-based and
    semantic routing degrade gracefully via single-selection (FR-028, FR-029).
  - A routing policy's own `suspendDuration` goes inert when failover is attached, with the override
    surfaced rather than silent, and unchanged behavior when used standalone (FR-026a/b/c).
- Correction carried into the spec: the existing `model-round-robin` "automatic failover" does NOT
  re-attempt a failing request (`gateway/it/features/model-round-robin.feature:849` asserts the
  failing request returns 500 to the client). Same-request chain traversal is new work, now stated
  explicitly in Assumptions.
- Iteration 4 (2026-10-22, second `/speckit-clarify`): One clarification — the failover policy keeps
  its own target list, but it becomes **optional** when an adopting routing policy is attached, and
  acts as a **last-resort tail** when one is (FR-001a, FR-001b, FR-006a, FR-024). Resolves the
  double-authoring problem in the fully-overlapping case and gives the out-of-rotation premium model
  a home. All 16 items still pass.
- Iteration 5 (2026-10-22, third `/speckit-clarify`): One clarification — same-request re-attempt
  (FR-008) is non-negotiable, and adding the missing re-dispatch capability at the gateway routing
  layer is in scope, to be justified in the plan's Complexity Tracking table. Feasibility probe
  findings recorded in Assumptions: per-attempt upstream steering already exists (policy-set upstream
  directive → header-based cluster selection → route cache cleared); no Envoy retry configuration is
  generated by the controller today. All 16 items still pass.
- Iteration 6 (2026-10-22, fourth `/speckit-clarify`): Upstream-proxy research performed. One
  clarification — every failover attempt must carry the request-body mutations applied by preceding
  policies (masking, guardrails, prompt decoration); an attempt that cannot preserve them fails and
  is recorded rather than sending unmutated content (FR-012a/b/c, SC-010). Proxy-level constraints
  recorded in Assumptions: retries stay within the selected upstream group; per-attempt work must run
  at the position that re-executes per attempt; body mutations are at risk when a later attempt
  rebuilds the request. All 16 items still pass.
- Iteration 7 (2026-10-22, fifth `/speckit-clarify`): Mechanism research completed at the user's
  direction. Retry-indexed upstream grouping was evaluated and rejected — it orders targets
  statically and cannot accept a per-request ranking without per-permutation configuration, which
  FR-021 forbids. Adopted chain re-entry instead, adding FR-012d through FR-012g (policy execution
  classes, once-per-client-request side effects, client-invisible attempts), two edge cases, and
  SC-011. One element remains unvalidated by any reference implementation and is assigned to Phase 0
  with a named fallback. All 16 items still pass.
- Iteration 8 (2026-10-23, `/speckit-clarify`): Customer requirements from ECI
  (wso2-apim-internal#18469) mapped against the spec. Points 1, 2, 5 and 6 were already covered by
  target identity, User Story 2, the probing state and the telemetry requirements. Two gaps closed:
  windowed error-rate suspension with a minimum sample size (FR-018a/b/c/d, ECI point 3) and
  aggregate latency suspension that keeps the per-attempt timeout as a request bound only
  (FR-018e/f, ECI point 4). All 16 items still pass.
- Iteration 9 (2026-10-23, `/speckit-clarify`): Probe-based recovery **replaced** by escalating
  backoff. A suspension that expires returns the target to full rotation; a further failure doubles
  the duration up to `maxDurationSeconds`; the duration resets to base only after
  `backoffResetSeconds` of healthy operation (FR-019, FR-019a-d). The `probing` state, probe traffic
  and `recovery.probeSuccesses` are removed throughout. This also dissolves the earlier open question
  about where a probing target sits in the ranked list — there is no probe traffic to place, so
  FR-021 is never overridden. All 16 items still pass.
- Iteration 10 (2026-10-23, `/speckit-clarify`): API-kind applicability settled. No kind allowlist —
  attachable wherever model targets resolve (`RestApi` and `LlmProxy` today), matching
  `model-round-robin`, which the repo shows already runs on `RestApi`. Unresolvable targets are
  rejected at deployment rather than being a silent runtime no-op (FR-030a/b). Isolation made an
  explicit, tested requirement: generated config is scoped to the attaching operation and must not
  mutate shared provider upstreams other APIs depend on (FR-030c/d, SC-012a). Scope wording that
  called plain REST out of scope was corrected, since model policies already run on `RestApi`.
  All 16 items still pass.
- Iteration 11 (2026-10-23, `/speckit-clarify`): Deployment-time rejection **reversed** to a fully
  silent no-op, correcting iteration 10. Evidence supported the reversal: the controller rejects no
  deployment today for an unresolvable policy reference, so rejecting would have made failover the
  first policy to block a GitOps deployment over an environment mismatch. Unresolvable targets are
  skipped (FR-006a); a policy with nothing to work with is inert and indistinguishable from being
  absent, with no telemetry (FR-030b/e); only schema-level errors are still rejected (FR-006).
  Recorded tradeoff: a misconfigured failover is now undetectable until the outage it was meant to
  survive. All 16 items still pass.
- Terminology note: "policy", "provider configuration", "routing policy", and "AI proxy API" are
